# Storefront visual audit

Дата: 2026-07-21. Среда: production `https://ggcar.ru/storefront/`. Основной viewport: 1440x900, дополнительно проверены 1280x800, 1600x900, 1920x1080 и 768x1024.

## Главная

Хорошо: светлая стилистика G-Garage сохранена, hero использует утвержденное автомобильное изображение, поиск и три режима подбора видны в первом экране, header не занимает чрезмерную высоту.

Проблемы до исправлений: вверху страницы отображался технический артефакт `` `n`` из marker-замены. Исправлено настоящим переносом строки в `storefront/index.html`.

Остаточно: много повторяющихся карточек с одинаковой структурой. Для следующего этапа стоит добавить больше различий в промо и доверительные блоки.

## Каталог

Хорошо: sidebar отделен, сетка 4 товара в ряд на 1440 px, изображения не растянуты, карточки одинаковой высоты, CTA заметные.

Остаточно: фильтры выглядят функционально, но сухо. Нужна более явная зона примененных фильтров при сложной фильтрации.

## Карточка товара

Хорошо: три колонки, sticky purchase-блок, галерея и таблица сравнения читаются, CTA заметны.

Остаточно: характеристики в центральной колонке плотные; на следующем этапе лучше оформить их как полноценную desktop-таблицу с группами.

## Выбор автомобиля

Хорошо: stepper понятен, выбор сохраняется, переход в каталог работает.

Остаточно: сценарий пока линейный и тестовый, без поиска по марке/модели. Не выглядит как растянутая мобильная версия.

## VIN

Хорошо: форма и объяснение процесса разделены на две колонки, CTA понятен, успешное состояние заявки работает.

Остаточно: блок примера документа схематичный. Для доверия нужен реальный локальный пример изображения документа или аккуратная иллюстрация.

## Корзина

Хорошо: summary sticky, промокод и итог читаются, состояния цены/срока/остатка показаны.

Проблемы до исправлений: строки товаров были слишком пустыми на wide desktop. Исправлено добавлением качества, остатка и более плотной правой колонки.

Остаточно: на 1440 px в строках еще есть воздух; для следующего этапа можно добавить компактную таблицу поставки/совместимости.

## Checkout

Хорошо: поля имеют нормальную ширину, summary читается, validation показывает ошибку без очистки draft.

Остаточно: форма длинная и простая. Для следующего этапа стоит добавить визуальный прогресс по шагам.

## Личный кабинет

Хорошо: есть desktop shell с sidebar, текущим заказом, автомобилем, VIN-заявкой и рекомендуемыми действиями.

Остаточно: часть пунктов sidebar ведет в тестовые разделы, без глубокой детализации. Для MVP допустимо.

## Доставка

Хорошо: после исправления страница содержит реальный текст и быстрые действия.

Проблемы до исправлений: страница была пустой из-за подключения неправильного JS-модуля. Исправлено подключение `cart.js` для сервисного рендера.

Остаточно: контент минимальный, блок локальной схемы выглядит как placeholder.

## Возврат

Хорошо: есть короткий правдоподобный текст без неподтвержденных юридических обещаний.

Остаточно: нужна структура условий по типам товара и состояниям, но без backend это можно оставить на следующий этап.

## Контакты

Хорошо: страница больше не пустая, CTA на VIN и каталог видны.

Остаточно: контакты тестовые, доверие ограничено. Нужны реальные реквизиты и карта только после подтверждения данных.

## Header и footer

Хорошо: header единый на клиентских страницах, содержит город, график, каталог, поиск, авто, VIN, избранное, кабинет и корзину. Footer завершает страницы и не выглядит полностью пустым.

Остаточно: header плотный на 1280 px, но не ломается. Footer содержит тестовые данные и должен быть заменен реальными после business confirmation.

## Category images

Сравнение `assets/categories/*.png` и `storefront/assets/categories/*.png` показало совпадение SHA256 для всех шести PNG. Эти изображения выглядят лучше старых placeholder-вариантов, соответствуют светлому фону, без шахматного фона и без белой рамки. Root `assets/categories/*.png` остаются локально измененными и не добавлены в индекс; в storefront зафиксированы только копии внутри `storefront/assets/categories/`.

## Итог исправлений

Исправлено:

- удален видимый marker-артефакт на главной;
- сервисные страницы подключены к правильному renderer и больше не пустые;
- строки корзины стали информативнее;
- production deploy повторен с backup;
- финальная production-проверка дала 0 JS errors, 0 failed requests, 0 external assets, 0 horizontal scroll.
