## Типы значений

По первым 500 строкам данных:

- `Наименование`: текст
- `Свободно`: целые числа
- `Ед.изм`: текст
- `Цена`: decimal, формат встречается как `3,690,000.00`
- `Артикул`: смешанный тип: текст, числа, отдельные пустые и date-like значения

## Дубли

- Найдено 103 повторных нормализованных артикула.
- Так как бренд отсутствует, дубли нельзя безопасно объединять в Product.

## Что можно использовать напрямую

- `Наименование` -> кандидат в `Product.name`, если будет определен бренд.
- `Артикул` -> `Product.article`, `Product.normalizedArticle`, `SupplierOffer.supplierArticle`.
- `Цена` -> `SupplierOffer.purchasePrice` и временно `SupplierOffer.retailPrice`.
- `Свободно` -> `SupplierOffer.stockQuantity`.
- `Ед.изм` -> `Product.unit`.

## Что требует нормализации

- `Артикул`: trim, uppercase, удаление пробелов и дефисов только для `normalizedArticle`.
- `Цена`: убрать thousands separators, поддержать точку и запятую, хранить Decimal.
- `Свободно`: строго целое число, текстовые остатки не приводить молча.
- `Наименование`: trim и схлопывание повторных пробелов.

## Отсутствующие данные

В файле не найдены явные колонки:

- бренд;
- производитель;
- категория;
- склад;
- срок поставки;
- минимальная партия;
- валюта;
- несколько цен.

## Нельзя достоверно определить

- Бренд товара.
- Производителя товара.
- Категорию товара.
- Склад поставщика.
- Срок доставки.
- Розничную наценку или отдельную retail price.
- Валюту из файла. Для mapping задан default `RUB`, но это не доказательство из XLS.

## Mapping

Файл mapping: `backend/imports/mappings/orion.json`.

- `sheetName`: `Лист2`
- `headerRow`: `9`
- `name`: `Наименование`
- `article`: `Артикул`
- `unit`: `Ед.изм`
- `stock`: `Свободно`
- `purchasePrice`: `Цена`
- `retailPrice`: `Цена`
- `brand`: `null`
- `category`: `null`
- `warehouse`: default `ORION-MAIN`
- `currency`: default `RUB`

## Риски импорта

1. Product нельзя создавать без бренда, потому что уникальный ключ товара: `brand.normalizedName + product.normalizedArticle`.
2. Поставщика ОРИОН нельзя автоматически считать брендом товара.
3. Повторные артикулы без бренда нельзя безопасно объединить.
4. Некоторые артикулы выглядят как числа или date-like значения, их нужно сохранять как исходную строку и нормализовать отдельно.
5. Цена использует thousands separators; неверный парсер может исказить сумму.
6. Реальный импорт этого XLS на текущем mapping создаст `PriceImport` и `PriceImportRow`, но строки будут invalid/review с причиной `BRAND_REQUIRED`, без создания Product и SupplierOffer.
